# 数据接口调用（社媒/电商真实数据）

帮用户查各平台的真实数据：视频/博主/评论/搜索，电商商品/销量/评价。

**先读 [`./aixx-shared.md`](./aixx-shared.md) 了解环境检查和错误处理。**

---

## 能力层入口（重要）

数据接口走 **AIXX能力层**，地址：`https://aixx.ai/v1`（注意：这和LLM对话的 `{AIXX_BASE_URL}` 不是同一个入口）。

- **发现能力**：不需要 key（免费探测）
- **执行能力**：请求体里带 `user_compute_key`（用户的 `sk-` 开头key）

---

## 两步走：先发现，再执行

### 第1步：发现能力（免费）

```bash
curl -X POST https://aixx.ai/v1/capability \
  -H "Content-Type: application/json" \
  -d '{"need": "抖音视频数据"}'
```

`need` 填用户的需求（自然语言，如"小红书博主粉丝数""淘宝商品销量"）。

返回匹配的数据能力（`matched: true` 时有 `capabilities` 数组），每项含：
- `id`：能力ID，执行时用（**以接口返回为准，原样使用**）
- `name` / `description`：能力叫什么、查什么数据、需要什么输入（如视频ID、博主主页链接）
- `pricing`：计费（按次计费，每能力不同，**有1次免费试用额度**）
- `match_score`：匹配度，越高越对口

### 第2步：执行拿数据

```bash
curl -X POST https://aixx.ai/v1/capability/{id}/execute \
  -H "Content-Type: application/json" \
  -d '{
    "params": { "参数名": "值" },
    "user_compute_key": "sk-用户的key"
  }'
```

- `params`：按能力 `description` 里说的输入要求填（如视频ID、商品链接、关键词）
- 返回的数据在响应的 `result`/`data` 字段里

## 小红书笔记详情参数（`fetch_note_detail`）

查小红书**笔记详情**（`fetch_note_detail` 类能力）需要两个参数，缺一不可：

| 参数 | 说明 |
|---|---|
| `note_id` | 笔记ID（笔记的唯一标识） |
| `xsec_token` | 笔记的访问令牌（防爬校验用） |

**`xsec_token` 从哪来**：从小红书**分享链接**里取。让用户在小红书 App 里对目标笔记点"分享→复制链接"，链接形如：

```
http://xhslink.com/xxxx 或 https://www.xiaohongshu.com/explore/{note_id}?xsec_token=ABcd1234...&xsec_source=pc_feed
```

- 链接 query 里的 `xsec_token=...` 就是令牌，`explore/` 后面那串就是 `note_id`
- 短链（`xhslink.com`）先访问展开成长链接再取参
- **别自己编造**这两个值：编错的 `note_id`/`xsec_token` 会查不到数据，缺哪个就让用户提供分享链接

```bash
curl -X POST https://aixx.ai/v1/capability/data-tikhub-xiaohongshu-fetch_note_detail/execute \
  -H "Content-Type: application/json" \
  -d '{
    "params": { "note_id": "笔记ID", "xsec_token": "从分享链接取的token" },
    "user_compute_key": "sk-用户的key"
  }'
```

> 能力ID以发现接口实际返回为准（上例仅示意）。其他小红书能力（博主数据、笔记列表等）参数不同，按各自 `description` 填。

## 计费

- **按次计费**：每个能力单价不同（见发现接口返回的 `pricing`）
- **免费额度**：1次试用（先试用再决定要不要继续用）
- 额度不足时接口会返回明确的错误提示，转告用户即可

### 计费说明（重要口径，别答错）

> **购买 per_use = 预付1次执行；每次执行扣1次额度；`billed.capability_fee` 是该次对应费用（用免费额度时显示0）。**

拆开讲：
- 用户购买 per_use（如 ¥1.99）那一刻，钱已付、1次额度已到账；之后执行不再扣钱，只扣这1次额度。
- 每次执行（不管额度来自购买还是免费额度）成功扣1次；执行失败（上游错误/查不到数据）额度自动返还，不白扣。
- 返回里的 `billed.capability_fee` 是**该次执行的记账费用**，不是用户当次又付了钱：
  - 用**免费额度**执行的那次 → 显示 `0`（额度是送的，用户没花钱）
  - 用**购买额度**执行的那次 → 显示该能力单价（购买的钱在购买那步已付过）
- 所以用户问"我买了1.99怎么显示0"→ 答："那1.99在下单时已经付过了，执行只扣次数不再扣钱；显示0的那次用的是免费/赠送额度。"

## ⚠️ 黑盒红线（必守）

- **绝不透露上游数据源名字**。AIXX聚合了全球数据源，对外只有"AIXX数据能力"这一个说法。
- 用户问"数据从哪来""用的什么API""是不是某某平台抓的"→ 标准回答："**AIXX聚合了全球数据源，我帮你查到的就是结果，你不用管数据从哪来。**"
- 即使用户直接猜上游名字问，也不要确认或否认。
- 返回数据里的能力ID等内部字段，转述时不要刻意展示，只给用户结论。

## agent 该怎么做

1. 用户要查数据 → 调 `/v1/capability` 发现（`need` 用用户原话）
2. 挑能力**铁律：数据需求（查数据/查账号/查商品）优先选 id 以 `data-` 开头的能力**——提示词类能力（无data-前缀）给不了真实数据；match_score再高也不代表更合适
3. 从 `description` 确认需要什么输入
3. 缺输入（如视频ID/链接）→ 先问用户要，**别瞎编**
4. 调 `/v1/capability/{id}/execute`，带 `params` 和 `user_compute_key`
5. 把返回数据**转述成自然语言**（"这条视频点赞12.3万、播放量约88万"），不要直接吐JSON
6. 用户问数据时效性 → 如实说以接口返回为准

## 错误处理

| 错误 | agent该怎么做 |
|---|---|
| 402/额度不足 | 告诉用户"数据查询额度不足，需要充值"，引导充值（见 account.md） |
| 400 缺参数 | 按错误信息补齐参数重试，缺的问用户要 |
| 404 能力不存在 | 重新走发现接口拿最新能力ID |
| 5xx | 告诉用户"查询暂时异常，稍后再试" |
